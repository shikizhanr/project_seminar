# Архитектура

```text
Expo / React Native ─┐
Telegram bot ────────┼── REST / JWT ── FastAPI ── PostgreSQL
Swagger UI ──────────┘                  │    └──── Redis (кэш dashboard)
                                       ├───────── ML lapse predictor
                                       └───────── Ollama qwen3:0.6b
```

## Модули

- `backend/app/api` — HTTP-контракты: авторизация, привычки, аналитика, социальные функции.
- `backend/app/models` — SQLAlchemy-модели пользователей, привычек, отметок и подписок.
- `backend/app/services/prediction.py` — bootstrap-модель риска и объясняющие факторы.
- `backend/app/services/analytics.py` — серии, регулярность, 14-дневный тренд и XP.
- `backend/app/services/motivation.py` — контекстные мотивационные сообщения.
- `mobile` — Expo-клиент с авторизацией, привычками и экраном прогресса.
- `bot` — Telegram-команды для отметок и краткой статистики.

## ML-пайплайн

Признаки: день недели, текущая серия, доля выполнений за 7 дней, число недавних
пропусков, сложность, недельная цель и возраст привычки. Начальная модель
`HistGradientBoostingClassifier` обучается на воспроизводимой синтетической выборке.
Каждая сделанная отметка сохраняет рассчитанный на тот момент риск — это позволяет
после накопления реальных данных обучить следующую версию на фактической целевой
переменной `completed` без изменения API.

Ollama не заменяет прогнозирующую модель: она получает агрегированные результаты
аналитики и локально генерирует понятную рекомендацию. При недоступности Ollama
сервис возвращает детерминированный fallback, поэтому основная функциональность не
зависит от LLM.

Для production-версии следует добавить model registry, периодическое переобучение,
time-based validation, мониторинг drift и отдельное пользовательское согласие на
обработку поведенческих данных.

## Основные решения

- Архивация вместо физического удаления привычек сохраняет историю.
- Пользователь видит только собственные данные; рейтинг ограничен социальным кругом.
- Redis необязателен: при его недоступности API работает напрямую с БД.
- Риск сопровождается понятными факторами и рекомендацией, а не только числом.
